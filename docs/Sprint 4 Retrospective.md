Date: 28/10/2026
Present: Dan, Gene and Nick

## What went well?
- test coverage - we went back below 70%
- we fixed the lag immensely for chart redraw
- Changing our role responsibilities - played to our strengths for the final sprint
- Implementing `[Theory]` unit tests
- Code Reviews and PR reviews - we communicated more before pushing major changes, and more regularly reviewed and tested each others' work
- We had a better understanding of what other people were working on, *how* it worked and why. We delegated tasks while communicating our solo work
	- contributing factors:
		- improved commit messages
		- branch work
		- centralising the product backlog and tying it directly to Github and our code.
- Extending our Sprint 3 over the holidays, and dropping Spring 4
	- meant less changing of roles, which gave us more time to focus on and finish assigned tasks.
	- Less redundant Sprint documentation (i.e., one less review, plan, stand-up and retrospective)
- Using *Fine Code Coverage* to identify gaps in our testing.

## What didn't go well?

- communication of requirements
	- we weren't regularly reviewing the requirements, only the user stories
	- meant a lot of costly last minute changes
		- not just code, but documentation and unit tests too
- Acceptance Criteria
	- why? we didn't study the Scrum process enough
- We left coverage testing until too late, assuming incorrectly we had enough coverage

## What would we change next time?

- testing throughout
- basing our sprint plans on the core requirements, not just the product backlog
- Better understanding of core Scrum principles and practices so all ceremonies are conducted.
- Regularly reviewing requirements
- Defining acceptance criteria for each user story and other relevant artefacts.
